# 演示操作卡（v6 · 8 分钟交错版）

一句话理解:deck 里翻页讲,翻到三个"演示"页时,页里嵌着真实应用,照下表点按钮。

---

## 一、一次性准备(到教室后)

```bash
# 1. 起应用
.venv\Scripts\python.exe -m mybuddy.cli web --host 127.0.0.1 --port 8000

# 2. 起 deck 服务器(另开一个终端)
python scripts/demo_runner.py
```

3. 浏览器开 `http://127.0.0.1:8765/` → **F11 全屏**——这就是幻灯片,方向键翻页
4. 翻到第 5 页(演示·评估),页内应用里**登录 演示用户 / demo1234**
5. 应用"设置"里打开 **系统决策透视** 开关(演示按钮才会出现)
6. **另开一个浏览器标签** `http://127.0.0.1:8000`,登录 **admin / 123456**,停在管理后台
7. 回 deck 标签。准备完成。

## 二、上台前 60 秒

```bash
python scripts/demo_rehearsal.py --prep --rounds 0
```
(清掉积压的主动消息和练习冷却)

然后在演示页里看输入框右上角:显示「▶ 演示 1/3」即就绪;若显示"重置演示",**点它一下**归零。

## 三、演示中(全程只翻页 + 点三次按钮)

| 到第几页 | 做什么 | 说什么(要点) |
|---|---|---|
| 1–4 | 只翻页讲 | 问题 → 四个问题 → 设计·评估 |
| **5 演示·评估** | 页内应用点导航"评估"再点"心情日记" | "16 条目进度、依据哪句话打的分;这两页是预置演示数据" |
| 6 | 翻页讲 设计·陪伴 | 情绪判定 86%/85%,四条链路 |
| **7 演示·陪伴** | **点「▶ 演示 1/3」**,等回复时预告右侧决策记录;回复出后展开讲。**再点「▶ 演示 2/3」** | ①日常消息看"系统决策" ②焦虑消息出"感官旅行"卡,界面无术语 |
| 8 | 翻页讲 设计·安全 | 硬底线+语言层融合;图 1 数字 |
| **9 演示·安全** | **点「▶ 演示 3/3」** | "测试集里的原句,关键词方案漏掉的那条——即时直返,模型调用 0"(时间允许:断网重发;**切 admin 标签**看安全事件,再切回) |
| 10–13 | 快翻,汇总页停一下 | "数字来自四个测试集,明细在这几页,欢迎回来细看" |
| 14–16 | 翻页讲 | 架构五层 → 管线 → 完成度:"看得到的五样 / 看不到的五样" |
| 17–18 | 收尾 | 局限三条 → 总结 → Q&A |
| 19(备用) | 不主动翻 | 评委要求验证时:End 键到此页,点按钮当场跑测试 |

## 四、兜底

| 状况 | 动作 |
|---|---|
| 演示按钮失效 | 手打消息(三条原文在 deck 设计页底部蓝字提示条上) |
| 应用没响应 | 新标签开 127.0.0.1:8000 直接操作;再不行跳过演示页,讲 deck 数字,叙事完整成立 |
| 模型回复慢 | 不解释,借等待讲决策面板已有内容 |
| 被追问打断 | "总结后有专门页,先把这条线走完";弹药在讲稿备答口袋 |

## 五、排练(随便跑,不脏演示数据)

排练器已用**独立账号(排练用户,自动注册)**,演示用户的 220 条故事线不受影响:

```bash
python scripts/demo_rehearsal.py --prep --rounds 3
```

若演示数据仍被手动测试弄脏:停应用 → `.venv\Scripts\python.exe scripts/seed_demo.py` → 重启应用(admin 自动重建)。

## 六、禁语(现场自由说话避开)

想死 / 好累 / 不想活 / 去死 / 活够了 / 撑不下去——会误触危机层。演示消息以按钮为准。
不要输入 `/persona`(遗留命令会报错)。M3 之后不再发任何情绪类消息(警戒窗口会升格后续消息)。
