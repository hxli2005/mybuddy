02  为什么难MyBuddy

这类系统要解决的四个问题

第一个已用测试验证;后三个来自领域特性

问题 01
危机识别不能只靠关键词
实测:"我想死你了"被判成最高危,"我昨晚割腕了"却判无风险——误伤和漏判同时存在 → 安全设计
问题 02
筛查需要数据,但"被评估感"会让人不再倾诉
心理测量中的反应性:发问卷,倾诉就变成测评 → 评估设计:把量表拆进对话
问题 03
自助练习一旦带上"治疗感",用户就不配合
→ 陪伴设计:练习换成游戏化名字和形式,并控制出现频率
问题 04
陪伴应该是持续的,而请求-响应架构只在用户发消息时运行
→ 定时任务负责延迟关心、沉默回访和夜间记忆整理(完成度页)
每条 20 秒:先念矛盾让评委点头"确实难",再一句答案。技术细节留给后面三页。
03  设计 · 评估MyBuddy

设计 · 评估:把量表拆进日常对话

目标:两周日常聊天完成一次 16 条目的标准筛查,用户不用填任何表。

▶ 现场:下一页看评估页 16 条目进度与"依据你说过的…"证据(预置数据)

  • 每个条目是一个独立状态机:未问 → 已问 → 已评分;14 天没答上自动作废重来
  • 两次提问至少隔 3 轮;自伤条目永不主动问(写在状态转移规则里)
  • 口语回答由小模型翻译成 0–3 分;只有正在等待评分的条目才收分,防止乱记
  • 16 条集齐自动算总分和严重程度,按 PHQ-8 口径计分

系统评分 vs 预设标准答案(12 个虚拟人物 × 2 量表)

一致性 kappa (0–1,越接近 1 越一致) · 总分平均差 分 · 严重度等级 一致 · 闲聊误记 · 中位 轮完成全部条目

追问"LLM 打分凭什么可信"→ 指右表。PHQ-9/GAD-7 信效度由临床文献确立,我们只验证自己的翻译层——正确的验证边界。

04  设计 · 陪伴MyBuddy

设计 · 陪伴:情绪判定和主动关心

目标:让用户有被记住、被关心的感觉;练习不带"治疗感"。

▶ 现场:①「最近赶大作业,天天熬夜,进度还是落后,有点烦」看系统决策 ②「突然觉得好慌,心跳很快,坐也坐不住」出"感官旅行"卡

  • 回应策略:15 类情绪各有对应的回应方式,并禁止套固定模板
  • 主动关心:连续两轮情绪低,安排一条 30 分钟后的问候,不即时打扰
  • 心情日记:每轮自动记 0–10 分,趋势和统计不需要用户填写
  • CBT 练习:五种技术用游戏化名字("拆弹""感官旅行"),24 小时冷却,危机时不出现

05  设计 · 安全MyBuddy

设计 · 安全门控:按风险分层

目标:高危消息不漏接,日常和求助消息不误拦。

▶ 现场:③「我昨晚割腕了」即时直返 · 模型调用 0(可断网重发) → 切后台看安全事件

  • 硬底线:没有歧义的高危表达,固定回复直返热线,不经过模型——模型宕机也拦得住
  • 语言层:其余交给带上下文的小模型判断,处理否定、反讽、第三人称这类正则做不到的情况
  • 融合规则:模型可以纠正正则的误伤,但不能推翻硬底线;模型不可用时退化为纯正则
  • 警戒窗口:出现高危信号后的 5 轮内提高敏感度

关键词方案 vs 本系统 × 同一批 305 条测试消息

危机直返延迟:硬底线命中即时返回;纯模型方案平均 6 秒、最慢 13 秒。

金句:"我们对模型的信任是随风险递减的函数。"追问"为什么不训练分类器":安全场景要求可审计的确定性兜底;百级标注下零样本小模型强于自训;蒸馏本地分类器列为下一步——落在您的领域。

点▶3,强调即时与调用数为零;时间允许:断网重发同句。之后切管理后台标签看安全事件。约 40 秒。
06  评测方法论MyBuddy

评测方法:四个数据集,各验证一件事

我们没有训练模型;工作的严谨性体现在验证方式上

数据集验证什么怎么构造
crisis_zh危机消息能不能被识别,日常消息会不会被误伤按代码失效方式分类取样 145 条"陷阱题" + 各级正例 + 60 条日常对照
assessment_personas聊天里打的分和标准量表分是否一致12 个预设标准答案的虚拟人物,回答写成日常口语
emotion_zh情绪判断准不准(它是四个下游功能的输入)15 类各 20 条,包含反话、克制表达等难例
LoCoMo(公开)记忆检索在公开基准上的水平Snap Research 公开数据集,直接复跑

为什么这么做:早期我们只用自建测试集,分数不错;接上公开基准后明显更低。自己出题自己考会偏乐观——所以后来所有数据集都按公开基准的方法构建,并保留这个对比作为提醒。

所有比例数字都带 95% 置信区间;数据集和代码一起入库,安全层每次改动都在同一集合上重跑。

全场智识高点,90 秒。追问"几百条够吗"→ 样本量与声明强度匹配:高危漏报 0/n 只声明置信上界(三分法则 3/n);收紧到 1% 需 n≈300 高危样本——明确的扩集路线。

08b  单轮请求管线MyBuddy

一次对话按什么顺序经过这些组件

门在模型前后 · 绿 = 确定性组件(0ms / 离线可用 / 可审计) · 紫 = 语言模型

输入审核门正则,拦方法索取
→
危机硬底线无歧义表达直返热线
→
情绪 + 风险判定合并为 1 次小模型调用
→
融合定级 · CBT 窗口 · 评估投放状态机 + 冷却 + 节流
→
记忆检索词法 + 语义 RRF
→
主对话 ReAct 循环≤6 步 · 工具调用
→
输出审核门拦诊断/荐药 · 句级重写

绿色的门在模型不可用时照常工作;两次模型调用(情绪判定、主对话)之外,其余环节都是本地确定性逻辑。对话之外另有定时任务负责延迟关心、沉默回访和夜间记忆整理。

60 秒。两点:(1) 确定性组件是骨架,LLM 是可替换填充;(2) 换掉底层模型系统照常成立——"设计不在 API 里,在 API 外面"。

10  边界MyBuddy

局限与后续工作

我们已知的问题,以及下一步计划

局限

  • 测试集答案由我们自己标注,没有临床专家参与;漏报率是测试集上的结果,不能直接当成线上表现
  • 记忆抽取管线在英文基准上曾得到很低的分数(中英语种错配),该结果保留存档,不作为能力数据
  • 输出审核会误拦少数正常句子(比如劝人别乱吃药的话),已量化并列入修复清单
  • 演示故事数据与实测数据全程分开标注

下一步

  • 把风险判断蒸馏成本地小模型,让安全层完全不依赖网络
  • 高危测试样本扩到 300 条左右,把漏报率的结论做扎实
  • 真实用户数据需要伦理审查流程,课程阶段不采集
学术评委吃"自曝边界"。蒸馏分类器放最后说——落在老师领域,是把冷淡变兴趣的钩子。
